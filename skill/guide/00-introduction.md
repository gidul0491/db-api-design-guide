# 웹 애플리케이션 설계 가이드

- **적용** RDBMS 기반 웹 애플리케이션

- **인용** 2-4-3 처럼 절·항 번호로

이 문서는 웹 애플리케이션의 스키마와 서버 코드를 어떤 규칙으로 만들지 정한 것입니다. 테이블을 어디까지 쪼개고, 이름을 어떻게 짓고, 코드를 어느 계층에 두고, API를 어떤 모양으로 내보내는지를 다룹니다.

규칙마다 왜 그런지를 함께 적었습니다. 이유를 모르면 상황이 달라졌을 때 그 규칙을 언제 깨도 되는지 판단할 수 없기 때문입니다.

조직의 운영 방식에 따라 어느 쪽이 맞는지가 갈리는 항목이 있습니다. 그런 자리에는 한쪽을 정해 두는 대신 양쪽의 판단 근거를 적었습니다. 프로젝트를 시작할 때 한쪽으로 정하고, 정한 것을 전체에서 지키면 됩니다.

규칙 자체는 특정 스택에 기대지 않게 쓰고, 예시와 코드 조각만 Node.js·Express·MySQL 8 기준으로 답니다.
