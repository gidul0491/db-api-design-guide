# 3장. 민감정보 저장

## 3-1 암호문 컬럼

1.  **주민등록번호, 전화번호, 이메일 같은 민감정보는 평문 컬럼으로 두지 않습니다.**

    덤프·백업·로그·조회 화면으로 빠져나갈 경로가 많고, 한 번 새어 나가면 회수할 수 없습니다.

2.  **암호문은** `_encrypted` **접미사를 붙인** `varchar` **컬럼에 저장합니다.**

    이름만 보고 평문이 아님을 알 수 있어야 조회·로그 코드에서 실수로 내보내지 않습니다.

3.  **저장하기 전에 값의 형태를 하나로 맞춥니다. 암호문과 해시를 같은 정규화된 값에서 만듭니다.**

    하이픈과 공백을 지웁니다. 해시 쪽은 이걸 빠뜨리면 같은 사람의 전화번호가 `010-1234-5678`과 `01012345678`로 들어와 서로 다른 해시가 되고, 중복 판정과 조회가 조용히 깨집니다. 발견했을 때는 이미 합치기 어렵습니다. 암호문 쪽은 깨지지는 않지만 같은 번호가 행마다 다른 형태로 복호화되어, 화면에 뿌릴 때와 외부로 보낼 때마다 정규화 코드가 따로 붙습니다. 하이픈을 넣어 보여주는 것은 애플리케이션의 일입니다.

4.  **암호문 값 안에 알고리즘과 키와 초기화 벡터를 함께 담습니다 —** `{알고리즘}.{모드}.{키}.{IV}.{암호문}`

    이 값 하나만 있으면 무엇으로 어떻게 잠갔는지가 전부 나와야 합니다. 그래야 알고리즘을 바꾸거나 키를 바꿀 때 기존 값을 그대로 두고 새로 저장하는 값부터 적용할 수 있습니다. 어느 하나라도 값 밖에 두면 그것을 바꾸는 순간 전체를 한꺼번에 다시 암호화해야 하고, 키 자리를 비워 두면 3-5-4의 교체 절차가 성립하지 않습니다. 키 자리에는 키 이름과 세대만 적습니다. 키 자체는 절대 들어가지 않습니다. 구분자는 마침표를 쓰고 IV와 암호문은 base64url로 패딩 없이 담습니다. base64url 알파벳에 마침표가 없어 충돌하지 않고, JWT·JWE가 쓰는 방식이라 상대가 설명 없이 알아봅니다. `$`는 셸에서 변수로 해석되어 큰따옴표 안에 넣는 순간 값이 사라집니다. 같은 형식을 API 전송에도 그대로 쓰면 경계에서 변환할 일이 없습니다.
    ```
    컬럼   social_number_encrypted
    저장값 aes256.gcm.social-number-k2.v5zpMhSCBhtlg5lP.-oQd-99fsXtdaBgUAMPyE_fQnVliHW_LlthFKzk
           알고리즘 모드  키           초기화 벡터      암호문 + 인증 태그

    조각별 길이 (주민등록번호 13자리, AES-256-GCM 기준)
      초기화 벡터  12바이트  → base64url 16글자
      암호문        13바이트 + 인증 태그 16바이트 = 29바이트 → base64url 39글자
      전체          위 예시 기준 84글자. 키 이름과 평문 길이에 따라 달라진다
    ```
5.  **대칭키 암호는 AES-256을 쓰고 GCM처럼 변조까지 잡아내는 모드를 먼저 고려합니다. 초기화 벡터는 값을 저장할 때마다 새로 뽑은 난수를 씁니다.**

    ECB 모드와 고정된 초기화 벡터는 쓰지 않습니다. 같은 평문이 항상 같은 암호문이 되어, 복호화하지 않고도 같은 값을 가진 행을 서로 찾아낼 수 있습니다. GCM을 쓰면 인증 태그가 함께 나오는데, 이것을 어디에 둘지도 형식에 포함됩니다. 128비트 태그를 암호문 뒤에 이어 붙여 마지막 조각 안에 함께 담습니다. 태그를 따로 떼어 보관하거나 버리면 변조를 잡아내지 못해 GCM을 쓰는 이유가 사라집니다. 블록 모드를 쓰기로 했다면 패딩 방식도 같은 자리에 적어 둡니다.

6.  **화면에 표시할 때 가리는 처리는 애플리케이션에서 하고, 가린 값을 원본 대신 저장하지 않습니다.**

    가린 값만 남기면 원본이 필요할 때 되돌릴 수 없고, 가림 규칙이 바뀌면 저장된 값을 전부 다시 만들어야 합니다.

## 3-2 검색용 해시

1.  **검색과 중복 판정은** `_hash` **접미사를 붙인** `char(64)` **컬럼으로 합니다.**

    암호문은 같은 값이라도 매번 달라 조회 조건으로 쓸 수 없습니다. 해시는 같은 값이면 같은 결과라 인덱스를 걸 수 있습니다.

2.  **해시는 서버가 보관하는 키를 섞은 HMAC으로 만듭니다. 키 없는 단순 해시를 쓰지 않습니다.**

    주민등록번호나 전화번호는 만들 수 있는 조합이 정해져 있어서, 해시 컬럼만 새어 나가도 전부 대입해 원본을 되찾을 수 있습니다.

3.  **해시용 키와 암호화용 키는 분리해 보관합니다.**

    한쪽이 노출돼도 다른 쪽이 버팁니다.

## 3-3 비밀번호

1.  **비밀번호는 검색용 해시와 다른 방식으로 저장합니다. bcrypt나 argon2처럼 일부러 느리게 만든 해시를 씁니다.**

    검색용 해시는 조회할 때마다 계산하므로 빨라야 하지만, 비밀번호는 그 빠르기가 그대로 대입 속도가 됩니다. 한 번의 계산이 오래 걸릴수록, 해시가 새어 나가도 원본을 알아내기 어려워집니다.

2.  **느린 해시를 쓰는 대신 로그인 시도 횟수를 제한하는 장치를 함께 둡니다.**

    느린 계산은 로그인할 때와 비밀번호를 바꿀 때만 들지만, 그 비용을 노린 요청이 몰리면 서버가 그대로 부담을 집니다.

## 3-4 복호화 지점

1.  **복호화는 서비스 계층 한 곳에서만 하고, 그 지점에서 접근 이력을 남깁니다.**

    여러 곳에서 복호화하면 이력을 남기지 않는 경로가 생깁니다. 누가 언제 무엇을 열람했는지 답할 수 없으면 사고가 났을 때 피해 범위를 정할 수 없습니다.

2.  **접근 이력은 로그가 아니라 테이블에 남깁니다.**

    로그는 기간이 지나면 지워집니다. 열람 이력은 나중에 조회해서 답해야 하는 자료입니다.

3.  **민감정보의 보관 기간과 파기 방법을 스키마를 정할 때 함께 정합니다.**

    나중에 정하려 하면 어느 행이 언제 들어왔는지, 지워도 되는지를 판단할 근거가 이미 없습니다. 파기는 행 삭제가 아니라 해당 컬럼만 비우는 방식이 되는 경우가 많으므로, 비워도 나머지 업무가 돌아가는지를 미리 봐야 합니다.

## 3-5 키 관리

1.  **키를 코드와 저장소에 두지 않습니다. 실행 환경이 주입한 값을 읽습니다.**

    저장소에 한 번 들어간 값은 지워도 이력에 남습니다. 저장소를 볼 수 있는 사람 전부가 키를 볼 수 있다는 뜻이고, 외주나 인수인계로 접근 권한이 오간 이력까지 따라가야 피해 범위를 셀 수 있습니다.

2.  **환경마다 다른 키를 씁니다. 운영 키는 개발자 로컬에 내려오지 않습니다.**

    같은 키를 쓰면 개발 환경에서 새어 나간 키로 운영 데이터가 열립니다. 개발·테스트 데이터가 운영 키로 암호화되어 섞이는 문제도 함께 생깁니다.

3.  **키마다 이름과 세대 번호를 붙이고, 3-1-4의 키 자리에 그 이름을 적습니다.**

    `social-number-k2`처럼 무엇을 잠그는 키인지와 몇 번째 세대인지가 드러나게 짓습니다. 어느 키로 잠갔는지 값이 스스로 답하지 못하면, 키를 바꾸는 순간 옛 값을 열 방법이 없습니다. 이름만 적고 키 자체는 담지 않습니다.

4.  **키를 바꾸는 절차를 미리 적어 둡니다.**

    순서는 새 키를 추가하고, 새로 저장하는 값부터 새 키로 잠그고, 옛 키는 복호화 전용으로 남겨 두고, 옛 키로 잠긴 값이 없어진 뒤에 폐기하는 것입니다. 전체를 한 번에 다시 암호화하는 방식은 도중에 실패하면 어느 행이 어느 키인지 알 수 없게 되므로, 값마다 세대가 적혀 있는 3번이 전제입니다.

5.  **검색용 해시 키는 암호화 키와 바꾸는 방법이 다릅니다. 해시 컬럼을 하나 더 붙일 수 있게 만들어 둡니다.**

    암호문은 어느 키로 잠갔는지가 값 안에 적혀 있어 옛 값과 새 값이 한 컬럼에 섞여 있어도 됩니다. 해시는 조회 조건으로 쓰이기 때문에 그럴 수 없습니다. 한 컬럼에 두 세대가 섞이면 어느 쪽으로 찾아야 할지 알 수 없습니다. 그래서 새 키로 만든 해시 컬럼을 하나 더 두고, 원본을 복호화해 그 컬럼을 채우고, 다 채운 뒤 조회를 새 컬럼으로 옮기고 옛 컬럼을 지웁니다. 그동안 조회는 멈추지 않습니다. 2-10의 컬럼 추가 절차를 그대로 따르면 됩니다.

6.  **키를 꺼내 볼 수 있는 사람을 정하고, 그 수를 최소로 둡니다.**

    전부가 볼 수 있는 키는 없는 것과 같습니다. 사람이 나갈 때 무엇을 바꿔야 하는지도 이 목록이 답합니다.
